# 细则：为什么是这六条，以及什么时候会错

本文件是 SKILL.md 的展开层。只在需要判边界或解释误判时读。

## 一、判定语义（每条规则的失败条件，写成可反驳的形式）

**R1 相对时间。** 失败条件：正文出现无法由收件人独立解析的时间指代。判定不看上下文语气，只看措辞清单（`this morning / today / yesterday / last week / 今早 / 昨天 / 上周 / 上午 09:20`）。
为什么必须绝对：相对时间在**收件人**那里没有锚点，而写的人有锚点——两者差一天时，错误恰好落在收信人眼里，无法用“本意”补救。2026-11-20 就是 11-19 的信被写成 “this morning”。
例外：引用对方原话里的相对时间（“your note of this morning”）仍算命中——保留原话就该保留原文日期，而不是把相对词搬进自己的叙述。

**R2 旧信必须存在且带日期。** 失败条件：出现“我发的那封 / the message I sent / 上一封”等指代，同时（a）该地址历史上从未有发出记录，或（b）正文没有任何绝对日期。
为什么要两条：存在性防“凭记忆引用”，日期防“引用正确但读者定位不到”。只有一条都能被绕过：真实存在但写成 “last week”，读者仍要翻邮箱。

**R3 不得假设沉默。** 失败条件：正文出现“收到了吗 / Did it arrive”类句式，且（a）被引用那封之后已有来信，或（b）最后一封之后已有来信。
为什么取两个锚点：正文常引用较早那封（“我 08:20 发的”），而邮箱里最新一封可能更晚；只看“最后一封”会漏掉 08:20→10:49 这种真实形态。
例外：正文明确承认对方已回并转向别的议题（“your reply of 10:49 is on record; one open item”）不算命中——这正是黄金集 c10 的对照。

**R4 24 小时窗口。** 失败条件：与上一封的间隔 < 24h 且期间无来信。
为什么是 24 小时而不是“看情况”：可测、可复算、不依赖判断者情绪。窗口内对方来信即解除，因为那是对方给出的新理由。
已知粗糙处：跨时区节假日、明确约好的次日跟进会被一并拦下——此时应改写成“按约定”，或由人显式放行（门禁是闸，不是法官）。

**R5 时刻必须在线索里。** 失败条件：正文出现 `HH:MM`，而该时刻既不在 sent 也不在 inbound。
为什么双向：正文既可能引自己的发送时刻，也可能引对方的回信时刻，只查单向会误伤后者。

**R6 站位断言。** 失败条件：出现断崖 / 全面超越 / 首创 / state-of-the-art / best-in-class / unmatched 等。
为什么在外发场景设这一条：这类词不可测、不可反驳，一旦被对方拿反例打脸，损失的是此前所有可测结论的可信度。

**R0 提示级。** 对方来信比我们最后一封新 → 提示“该回信”，不改裁决。

## 二、六类反模式与它们的真实代价

| 反模式 | 表面收益 | 真实代价 |
|---|---|---|
| 把昨天的信说成今早 | 显得跟进及时 | 对方一眼看出没核记录，此后所有数字都被打折 |
| 对已回的人问“收到了吗” | 省一次翻邮箱 | 等于宣布没读回信，是把合作方当成没回应 |
| 24 小时内二次追 | 提高“被看到”的概率 | 压力感上升，回复质量下降，且把对方推到“先关掉” |
| 编一个“07:41 发的” | 叙事完整 | 可被邮箱时间戳逐条否证，属硬伤而非口误 |
| 站位词 | 气势 | 一旦被反例命中，前面所有可测结论一起贬值 |
| 引用旧信不给日期 | 行文简洁 | 读者要自己考古，多数不会去考 |

## 三、误判与豁免（写给使用者，不写进规则）

1. **首次联系**：无 sent 记录时，R2/R4 不触发；只有 R1/R5/R6 仍适用。
2. **对方主动要求再发**：R4 应由人放行；规则无法识别这种语境，这是有意的保守。
3. **正文引用第三方时间**（“他们 10:00 开会”）：R5 会命中并判红。处理办法是把第三方时间写清来源，或不用时刻而用日期。
4. **多收件人**：门禁按单地址评估；同一封信发给多人时，应逐地址跑一次，取最严结果。

## 四、如何接真实邮箱（不写凭据）

门禁本身不联网。调用方负责取线索，取法约束如下：

- 只读选择（IMAP `readonly=True`）取 `SENT` 与 `INBOX` 各若干封的 `Date/Subject`，转成上文 JSON；
- 授权码经操作系统凭据库或进程环境变量传入，**不得写进任何文件、日志、提交**；
- `now` 用调用当刻的带偏移时间戳，不要用本地裸时间；
- 发信步骤以 `gate.py check` 的退出码为准：`2` 即停，不许“先发后改”。

## 五、什么情况下不该用这个门禁

- 对方已明确“不要再联系”：不需要门禁，需要的是永久停手。
- 法定/合规通知、事故通报：时效优先，形式化核对会延误；应走另一条有审批的通道。
- 需要谈判语气判断的场合：本条看不到语气，只对事实对账。
