Parity — we publish the version we measured, and the original next to it

Our packages ship a condensed rewrite (v2.1.0-slim), not an excerpt of the source document. What we measure

  • Structure — can a machine find the entry, version, license?
  • Consistency — do the documented commands exist in the source?
  • Reproducibility — is there a golden set and a runner that actually runs?
  • Hygiene — absolute paths, secrets, leaked contact details
  • Discoverability — triggers, ecosystem links, machine-readable index
  • Licensing — a real license, not a claim

Reproduce it

git clone https://github.com/zhaoxinghua09-cell/lgd-skill-review.git
cd lgd-skill-review/bench
python bench.py

Refreshed automatically every day at 09:17 Beijing time. If you disagree with a number, the JSON is public and the runner is public.

Our ruler is tested too

It is easy to publish checks and never enforce them. So every published check has a probe that breaks it on purpose and asserts the score actually drops — 22 cases covering all 23 checks (one check shares its evidence with another), run in CI on every push:

python tests/rubric_probe.py
# 22/22 enforced

Two of those probes found real defects in this project: a junk scan that could never fire (its walk pruned the very directory it was looking for), and a flag check that recorded a mismatch without deducting. Both are fixed — and the third-party top went from 36 to 38 the moment the flag check started enforcing. The gap widened because the ruler got stricter, not because competitors got worse.

Get your skill reviewed — without talking to us

Open an issue with the review form. A bot fetches your public tarball, runs static analysis (it never executes your code), and replies with the score, the six-dimension breakdown, the blockers, and the order to fix them.
